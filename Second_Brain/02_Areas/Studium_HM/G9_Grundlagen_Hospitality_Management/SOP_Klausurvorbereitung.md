# G9 Hospitality Management — SOP Klausurvorbereitung

> Voraussetzung: [[02_Areas/Studium_HM/G3_Grundlagen_Hospitality/Konzepte|G3-Konzepte]] sitzen (Dienstleistungsmerkmale, Betriebsarten). Rechenmuster aus [[02_Areas/Studium_HM/G5_Internes_Rechnungswesen_Finanzierung/SOP_Klausurvorbereitung|G5]] wiederverwenden.

## 1. Themenreihenfolge

1. **KPI-Set (Occ, ADR, RevPAR & Co.)** — Rechen- UND Interpretationspunkte, kommt sicher dran
2. **Revenue Management** (Logik + Instrumente + Überbuchung)
3. **F&B-Kalkulation + Menu Engineering** — dankbare Rechenaufgaben
4. **Servicequalität** (GAP-Modell, Beschwerdemanagement)
5. **Organisation & Abteilungen** — Struktur-Lernstoff
6. **Budget/USALI-Grundzüge** — Restpunkte

## 2. Typische Aufgabentypen + Denkschritte

### Typ A: KPI-Berechnung und -Beurteilung
**Denkschritte:**
1. Formeln hinschreiben (aus [[02_Areas/Studium_HM/G9_Grundlagen_Hospitality_Management/Konzepte|Konzepte]]-Tabelle): Occ = verkaufte Zimmer/verfügbare Zimmer; ADR = Logisumsatz/verkaufte Zimmer; **RevPAR = Logisumsatz/VERFÜGBARE Zimmer = Occ × ADR**
2. Einsetzen, Einheiten (€, %) dazuschreiben
3. **Interpretieren im Dreieck:** RevPAR verbindet Preis (ADR) und Menge (Occ) — einzelne Kennzahl nie isoliert loben/tadeln. Hohe Occ + niedrige ADR = "verschenkt Preis"; hohe ADR + niedrige Occ = "verschenkt Menge"?
4. Vergleichsmaßstab nennen: Vorjahr, Budget, Comp Set (Marktvergleich) — ohne Benchmark keine Bewertung
5. Grenzen: RevPAR ignoriert F&B/Nebenerlöse (→ TRevPAR) und Kosten (→ GOPPAR)
**Häufiger Fehler:** RevPAR mit verkauften statt verfügbaren Zimmern; Occ in die ADR-Formel gemischt.

### Typ B: Rate senken oder Auslastung opfern? (Entscheidungsfall)
**Denkschritte:**
1. Szenarien als Tabelle: Menge × Preis = Logisumsatz je Szenario
2. Variable Kosten pro belegtem Zimmer (CPOR variabel) abziehen → **DB je Szenario** (G5-Logik! Fixkosten sind kurzfristig irrelevant)
3. Zweitrundeneffekte qualitativ: Preisimage/Ratenintegrität (Rabatt heute senkt Zahlungsbereitschaft morgen), Verdrängung besser zahlender Last-Minute-Nachfrage, Kanalkosten (OTA-Kommission!)
4. Empfehlung mit Bedingungen formulieren
**Häufiger Fehler:** Umsatz statt Deckungsbeitrag vergleichen; Zweitrundeneffekte ([[00_System/Konzept_Bibliothek|Second-Order Thinking]]) weglassen.

### Typ C: F&B-Kalkulation
**Denkschritte:**
1. Wareneinsatz pro Portion aus Rezeptur (Menge × Einkaufspreis, Putzverlust/Schwund einrechnen!)
2. Zielaufschlag aus Ziel-Wareneinsatzquote: **Verkaufspreis netto = Wareneinsatz / Zielquote** (z. B. 25 % Quote → Faktor 4)
3. + USt (Speisen im Haus vs. außer Haus — Satz je Rechtslage prüfen) → Bruttopreis, psychologisch runden
4. Rückwärts prüfen: tatsächliche Wareneinsatzquote = Wareneinsatz/Nettoerlös
**Häufiger Fehler:** USt auf den Netto-Zielpreis vergessen; Quote auf Brutto gerechnet.

### Typ D: Menu Engineering
**Denkschritte:** Pro Gericht db (Preis − Wareneinsatz) und Absatzmenge → Vier Felder: **Star** (db hoch/Menge hoch → pushen, Preis testen), **Plowhorse/Renner** (db niedrig/Menge hoch → Preis leicht rauf oder Wareneinsatz runter), **Puzzle** (db hoch/Menge niedrig → Platzierung/Beschreibung verbessern), **Dog/Penner** (beides niedrig → streichen/ersetzen). Trennlinien: Durchschnitts-db und 70-%-Regel der Durchschnittsmenge (bzw. Skript-Konvention).

### Typ E: GAP-Modell anwenden
**Denkschritte:** Die 5 Lücken lokalisieren: GAP 1 Management kennt Erwartungen nicht (→ Gästebefragung) / GAP 2 Erwartung nicht in Standards übersetzt (→ SOPs) / GAP 3 Standards nicht gelebt (→ Training, Personaldecke) / GAP 4 Kommunikation verspricht zu viel (→ Marketing ehrlich) / GAP 5 = wahrgenommene Lücke Gast (Summe aus 1–4). Im Fall: Symptom → welche GAP(s) → Maßnahme je GAP.

## 3. Häufige Fehlerquellen (vor Abgabe prüfen)

- [ ] RevPAR-Basis = verfügbare Zimmer?
- [ ] RevPAR = Occ × ADR als Quercheck gerechnet?
- [ ] DB statt Umsatz bei Entscheidungen?
- [ ] OTA-Kommission als Kanalkosten berücksichtigt, wo relevant?
- [ ] Wareneinsatzquote auf NETTO-Erlös bezogen?
- [ ] Menu-Engineering-Achsen korrekt (db, nicht Umsatz!)?
- [ ] Benchmark bei jeder Kennzahlen-Beurteilung genannt?
- [ ] Bei Qualitätsfällen: konkrete GAP-Nummer + Maßnahme?
- [ ] Standard-Endkontrolle [[03_Resources/Lernmethoden_Referenz|§6]]
